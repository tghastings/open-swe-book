# Chapter 8 — Open Resources

Free, open-licensed, or freely accessible materials that reinforce this chapter. Types: 📘 open
text · 🎓 course · 📄 primary source · 🎥 video. Licenses vary and are noted where known.

## Foundations: what Git is and how it works (used in §8.1)

- 📘 **Scott Chacon & Ben Straub — *Pro Git* (2nd ed.)** —
  [git-scm.com/book](https://git-scm.com/book/en/v2). The canonical, complete reference and the
  primary source for most of this chapter: version control (§1.1), the snapshot model (§1.3),
  Git objects (§10.2), branching and merging (§3), and undoing things (§2.4, §7.7).
  *License: Creative Commons BY-NC-SA 3.0 — free to read and reuse.*
- 🎓 **MIT "The Missing Semester of Your CS Education" — Version Control (Git)** —
  [missing.csail.mit.edu](https://missing.csail.mit.edu/2020/version-control/). Teaches Git
  data-model-first, the same approach this chapter takes. *License: CC BY-NC-SA 4.0.*
- 📄 **Linus Torvalds — Git origin and the 2005 timeline (Wikipedia summary)** —
  [en.wikipedia.org/wiki/Git](https://en.wikipedia.org/wiki/Git). The BitKeeper dispute, the
  design goals, and how Git came to manage the Linux kernel. *Access: free.*

## Building the right mental model (used in §8.1, §8.3)

- 📘 **Julia Evans — *How Git Works* (Wizard Zines)** —
  [wizardzines.com/zines/git](https://wizardzines.com/zines/git/). Short, illustrated
  explanations aimed exactly at the mental-model gap that makes Git confusing; her free blog
  posts on [branches](https://jvns.ca/blog/2023/11/23/branches-intuition-reality/) and
  [HEAD](https://jvns.ca/blog/2024/03/08/how-head-works-in-git/) are excellent companions.
  *Access: blog posts free; the zine is a paid PDF.*
- 📄 **De Rosso & Jackson — "What's Wrong with Git?" and the conceptual redesign** —
  [onward13.pdf](https://spderosso.github.io/onward13.pdf),
  [oopsla16.pdf](https://spderosso.github.io/oopsla16.pdf). The research behind the claim that
  Git's difficulty is a conceptual-model problem, not a you problem. *Access: free PDFs.*

## Hands-on practice and everyday commands (used in §8.2, §8.4)

- 🎓 **Atlassian Git Tutorials** —
  [atlassian.com/git/tutorials](https://www.atlassian.com/git/tutorials). Clear, example-driven
  walkthroughs of the everyday commands, [merging vs. rebasing](https://www.atlassian.com/git/tutorials/merging-vs-rebasing),
  and [comparing team workflows](https://www.atlassian.com/git/tutorials/comparing-workflows).
  *Access: free.*
- 📄 **GitHub Docs — Git basics, GitHub Flow, and pull requests** —
  [docs.github.com](https://docs.github.com/en/get-started/using-github/github-flow). The
  mechanics of branches, [pull requests](https://docs.github.com/en/pull-requests), and
  [protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
  *Access: free.*
- 🎥 **"Oh Shit, Git!?!"** — [ohshitgit.com](https://ohshitgit.com/) (and the PG-rated
  [dangitgit.com](https://dangitgit.com/)). A recovery cookbook for the specific messes
  beginners create; keep it open next to your terminal. *Access: free.*

## Team workflows and conflicts (used in §8.4, §8.5)

- 📄 **Trunk-Based Development** — [trunkbaseddevelopment.com](https://trunkbaseddevelopment.com/).
  The reference for short-lived branches and daily integration, with the
  [DORA evidence](https://dora.dev/capabilities/trunk-based-development/) for why it correlates
  with elite delivery. *Access: free.*
- 📄 **Martin Fowler — "Patterns for Managing Source Code Branches"** —
  [martinfowler.com](https://martinfowler.com/articles/branching-patterns.html). A careful,
  vocabulary-building survey of branching patterns and their trade-offs. *Access: free.*
- 📄 **Vincent Driessen — "A successful Git branching model" (Gitflow), with the 2020 note** —
  [nvie.com](https://nvie.com/posts/a-successful-git-branching-model/). Read it *including* the
  author's own caveat about continuous delivery, discussed in §8.4.4. *Access: free.*

## Commit and history discipline (used in §8.6)

- 📄 **Chris Beams — "How to Write a Git Commit Message"** —
  [cbea.ms/git-commit](https://cbea.ms/git-commit/). The seven rules and the imperative-mood
  convention this chapter recommends. *Access: free.*
- 📄 **Conventional Commits 1.0.0** — [conventionalcommits.org](https://www.conventionalcommits.org/en/v1.0.0/)
  and **Semantic Versioning 2.0.0** — [semver.org](https://semver.org/). The prefix scheme and
  the version grammar that structured histories and releases build on. *Access: free.*

## Markdown and documentation (used in §8.7)

- 📄 **Markdown Guide — Basic and Extended Syntax** —
  [markdownguide.org](https://www.markdownguide.org/). The most practical reference for the
  syntax in §8.7, with a printable [cheat sheet](https://www.markdownguide.org/cheat-sheet/).
  *Access: free.*
- 📄 **CommonMark** — [commonmark.org](https://commonmark.org/) and **GitHub Flavored Markdown**
  — [github.github.com/gfm](https://github.github.com/gfm/). The standardized spec and the
  GitHub superset (tables, task lists) you will actually type. *Access: free.*
- 📄 **GitHub — Basic writing and formatting syntax** and **About READMEs** —
  [docs.github.com](https://docs.github.com/en/get-started/writing-on-github). How Markdown
  renders on GitHub, and what a README should contain. *Access: free.*
- 🎓 **Write the Docs — Docs as Code** —
  [writethedocs.org](https://www.writethedocs.org/guide/docs-as-code/) and **Make a README** —
  [makeareadme.com](https://www.makeareadme.com/). The philosophy behind keeping docs in the
  repo, and a template for the project README. *Access: free.*
